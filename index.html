Controle sua Smart TV pelo navegador

Philco / Android TV com pareamento: requer a ponte local (pasta bridge/) rodando no seu computador — veja o README dela. A TV mostra um código de pareamento na tela na primeira conexão.

Android TV / Google TV: Configurações → Rede e Internet → veja o IP conectado.

Sony Bravia: Configurações → Rede → Config. de rede doméstica → Controle IP → defina Autenticação como "Normal e Chave Pré-Compartilhada" e crie uma PSK (ex: 0000). O IP fica na mesma tela de Rede.

Roku: Configurações → Rede → Sobre.

Samsung: Configurações → Geral → Rede → Status da Rede.

LG: Configurações → Conexão → Wi-Fi (ícone de engrenagem na rede conectada).

A TV e o celular/computador precisam estar na mesma rede Wi-Fi.

Aviso de compatibilidade

Android TV com pareamento (Philco/Shield/TCL/genérico): usa o protocolo oficial Android TV Remote v2 da Google (o mesmo que mostra código na tela). Esse protocolo é TCP+TLS, algo que nenhum navegador consegue abrir — por isso esse modo depende de uma ponte local (pasta bridge/, roda com npm start na sua rede). Com a ponte rodando, o controle é completo de verdade.

Android TV / Google TV (sem ponte): usa o protocolo aberto DIAL, o mesmo do Chromecast, só para abrir apps direto na TV (Netflix, YouTube etc). Setas, volume e power não têm um protocolo aberto por HTTP nesse modo — por isso ficam esmaecidos na tela.

Sony Bravia (Android TV): usa o protocolo oficial IRCC-IP da Sony, que cobre setas, volume, canal, power e números de verdade, autenticado por uma chave PSK configurada na TV.

Roku: usa o ECP (protocolo oficial da Roku) — funciona sem senha.

Samsung: WebSocket local com pareamento — pode pedir para aceitar na tela da TV.

LG (webOS): exige um token pareado pelo app oficial da LG, que uma página web comum não consegue obter com segurança — por isso não está disponível aqui.

Sem contar a ponte local (que roda em Node.js), tudo sai direto do seu navegador para o IP local da TV — o servidor no Render nunca fala com a TV. Se um botão não responder: confirme a mesma rede Wi-Fi, o IP e, se aparecer bloqueio de "conteúdo misto" do HTTPS, permita "conteúdo não seguro" para este site.
